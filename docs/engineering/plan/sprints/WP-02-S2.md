## 2. Plan

### Decisions of the plan

- **DL-079** — no per-case seam in the server demo (architect, 2026-10-31). (1) **VasSonic:** no such seam. (2) **Why different:** S1 already tests `examples/server-demo/src/rqp.js` by URL through the harness (112/112); the demo app adds only its routes and its `Host` check, which its own tests cover. (3) **Skeptic:** a control endpoint in an example app invites copying into production code; the harness exists for exactly this. (4) **Decision:** drop the seam; the harness stays the only place with a control endpoint.
- **DL-080** — layout of the malformed suite (architect, 2026-10-31). `fixtures/malformed/legacy/FX-LEG-MAL-<NAME>/` in the format of `fixtures/legacy` (canonical profile only, `evidence: code-reading`, generated `expected.json`), with its own `pages/`; the runner runs it with `--suite legacy --fixtures fixtures/malformed/legacy` (no runner change; the ids start with `FX-LEG-`). `fixtures/malformed/seeds/` holds raw seed files without an expected result for the fuzz targets of WP-05 and WP-18 (legacy split, legacy request fields). The RQP negatives stay in `fixtures/rqp` (the markup and protocol suites already have them).
- **DL-081** — control endpoint of the lab harnesses (architect, 2026-10-31). The lab containers publish their ports on `127.0.0.1` of the host only (`tools/upstream-lab/start.sh`), so inside the container a request comes from the bridge address, not from loopback: a lab harness checks the `Host` field (CONTRACT.md §2) and `Content-Type`, not the peer address. The lab harnesses are Rivqen code around the unmodified upstream code; they serve the posted page with the posted status and fields of the application.

- **H-112** — phase B (human, 2026-10-31): the human frees the Data volume to at least 23 GB and starts Docker Desktop before phase B; phase A starts now.
