<Badge type="tip" text="FACT" /> Facts from the researcher (sources: crates.io, rustsec.org, sqlite.org, POSIX, the Rust `std` source, the crate READMEs; 2026-11-15):

- `rusqlite` 0.40.2, the version in [dependencies](/engineering/core/dependencies) until today, uses `libsqlite3-sys` 0.38.2, which has RUSTSEC-2026-0459 (fixed in 0.39.0 and later). The latest releases are 0.42.0 (2026-11-11) and 0.43.0 (2026-11-15).
- SQLite in WAL mode with `synchronous=NORMAL`: a commit can roll back after a power loss; the database stays consistent. `FULL` is durable.
- POSIX `rename` is atomic, but it cannot replace a directory that is not empty; a new directory entry needs an `fsync` of the parent directory. `File::sync_all` on Apple targets calls `F_FULLFSYNC`.
- `chacha20poly1305` 0.11.0 and `aes-gcm` 0.11.1 are stable releases; both families had one audit (NCC Group, 2020, no significant finding). `aes-gcm-siv` had no audit. `hmac` 0.13.0 depends only on `digest`. `cpufeatures` documents the AES detection on aarch64 for Linux, iOS and macOS; Android is not named.
- NOT FOUND: the NIST SP 800-38D text of the 2^32 limit for random 96-bit nonces (the document could not be read); a statement of Apple on Keychain items after an app is removed; what happens to Android Keystore keys when only the app data is cleared.
