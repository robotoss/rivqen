### Human decision of the plan

| ID | Question | Decision |
|---|---|---|
| H-160 | How the session finds the cache entry of a URL: the cache key holds the digests of the `Vary` values (identity §1, CL-12, H-124), but the session does not know the `Vary` names before it reads the entry, and the driver reads by the exact key only | **One entry per URL.** The key is the partition and the URL with no `Vary` entry; the entry stores the `Vary` names of its response with the keyed digests of the request values, and it is visible only to a request with the same values; a commit for other values replaces it. No change of the store format; 0 fixtures (the canonical servers send only `Vary: template-tag`, which does not count). Cost: a page whose `Vary` value changes between requests keeps one variant (a miss, never another variant). Not chosen: an index of variants (a new entry kind in `rivqen-cache` and `rivqen-store`, schema version 2); no commit for a response with `Vary` (pages with `Vary: Accept-Encoding` lose the cache) |
