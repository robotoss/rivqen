## 1. Scope and inputs

Input: the WP-17 audit of 2026-10-19 (sprint record [S3](/engineering/plan/sprints/WP-17-S3) §6): the rule-cost audit measured every rule on the markup corpus and found two over-tight rules at block level.

### Human decisions (2026-10-19)

| ID | Question | Decision |
|---|---|---|
| H-77 | D1: manifest-patch §4.2 item 2 rejects a patch for any `&` other than `&amp;` (patches lost for 16.6 % of small and 43.4 % of main block variants) | **N2c: check a character reference only at the scheme decision byte.** Find the decision byte of the raw value (skip bytes `00`–`20` at the start, then each `09`, `0A`, `0D` and each ASCII letter, digit, `+`, `-`, `.`). If it is not `&`, pass. If it is `&`: a numeric reference read from the raw bytes as the WHATWG tokenizer does (hex with `x`/`X`, leading zeros, `;` optional) rejects when its value is `00`–`20`, `:`, `+`, `-`, `.`, an ASCII digit or letter; `Tab;`, `NewLine;`, `colon;`, `fjlig;`, `period;` or `plus;` after the `&` rejects; anything else passes. Item 3 no longer replaces `&amp;`. Audit: rejected blocks 7.8 % → 1.6 % (small), main variants 43.4 % → 9.0 %; 7 000 000 generated values, 0 misses. The numeric reference MUST be read on the raw bytes, not on the normalized copy |
| H-78 | D2: M-22 forbids elements that are dangerous only in a patch (the whole page loses RQP) | **Move `script`, `style`, `link`, `meta`, `iframe`, `object`, `embed`, `base`, `basefont`, `bgsound` and M-22 item 5 (FOREIGN_ALLOWED) out of M-22 into the patch content rule** (manifest-patch §4 item 1: a client check on patched `html` content, next to the attribute rule; the server SHOULD send F when a changed block has them, as H-56). M-22 keeps DOCTYPE, `html`, `head`, `body`, `frameset`/`frame`, `plaintext`, `select`/`option`/`optgroup`, `title`, and (until a study) `noscript`, `template`, `textarea`, `noembed`, `noframes`, `xmp`. Audit: valid variants small 81 % → 91 %, main 35 % → 67 %; parse5 0 disagreements on 341 variants |
| H-79 | D3: a document whose first head content (`<meta>`, `<script>` …) comes before any `<head>` start tag gets no RQP (H-72) | **Allow after a check:** when the walk of manifest-patch §1.7 item 1 stops at a start tag `base`, `basefont`, `bgsound`, `link`, `meta`, `noframes`, `script`, `style` or `title` before any head start tag, the insertion point is the `<` of that tag (the manifest script implies the head). First a T-08a-style sweep in both scripting views; the client uses the same walk. +8 to 12 pages |
| H-80 | Process: fail-closed fixes with an obvious answer | **The architect decides a review fix that only makes a rule stricter, falls back to the normal page or F, and costs at most 2 corpus pages (0.25 %)**; recorded with the DL-028 four-part record and the corpus cost, listed in the merge request (AGENTS.md rule 3, decisions §1) |
| H-81 | The `public` partition (10 security decisions; no measurement of its benefit) | **Keep it in the spec, off by default:** an SDK uses `public` only when the app turns it on; WP-19 measures the benefit |
| H-82 | The legacy byte comparison dropped from the performance page | **Measure it again at the next measurement** with `LEGACY_URL` (tools/upstream-lab) when a VasSonic checkout is available; open item until then |
| H-83 | D5: `data:` URLs of images in patches | **Allow `data:` in `src`/`srcset` of `img` and `source` and in `poster` of `video`, after a fact check** (an image loaded from `data:`, also SVG, runs no script in browsers and WebViews; how WebViews handle `data:`); `javascript:` and `vbscript:` stay rejected everywhere |
| H-84 | D4: M-13 item 2 rejects any `&` in the type of a `script` (4 pages) | **Narrow it as H-77:** reject a `&` in the first type value only when it is followed by an ASCII letter, or starts a numeric reference whose value is `00`–`20`, an ASCII letter, digit, `/`, `+`, `-` or `.` |
| H-85 | M-09: unclosed table cells and rows (4–6 pages) | **Study** modelling the implied closure of a cell or row ("close the cell", the row pops to the table-family element) with parse5 in both views and the depth claim; then the human decides the rule |
| H-86 | D6: JSON-LD | **Allow `application/ld+json` as a format of a `json` block** (M-16 json type; manifest and patch format rules); JSON-LD is on about 60 % of valid pages |
