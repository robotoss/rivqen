# Legacy golden fixtures

<!-- SPDX-License-Identifier: Apache-2.0 -->
<!-- SPDX-FileCopyrightText: The Rivqen Authors -->

Golden fixtures for the server side of the legacy (VasSonic-compatible) protocol: one request to the server under test and the exact expected response. Every server (the Rust reference server of WP-03, the Node.js, Java and PHP SDKs) runs them with `server/conformance`. Catalog: `docs/engineering/protocol/fixtures.md` §3. Behavior: `docs/engineering/protocol/legacy-wire.md` §10 (rules C-01 to C-16). Profiles: ADR-005. Format fixed by the architect for WP-02 S1 (DL-067, DL-068). The client part of each fixture (`cache-before`, expected actions) is added before P3 (H-110).

Upstream: `Tencent/VasSonic` at `59936beff656d4b5718ff6444d6c5e001a2c5231`. Clean-room: no upstream code, comments, test code or sample HTML in this directory. The pages are Rivqen test pages.

## Layout

```text
fixtures/legacy/
├── pages/<page-id>.html            # application body bytes, exact
└── FX-LEG-<NAME>[--<JAVA|NODE|PHP>]/
    ├── case.json                   # written by a person
    └── expected.json               # generated by tools/legacy-fixtures/gen.mjs; never edited by hand
```

`FX-LEG-<NAME>` is a canonical fixture (`legacy-canonical`). `FX-LEG-<NAME>--JAVA` (or `--NODE`, `--PHP`) is a profile fixture: it replaces `FX-LEG-<NAME>` in the runs of that profile (DL-068).

## Canonical `case.json`

```json
{
  "id": "FX-LEG-DATA-CHANGE",
  "description": "Same template, data changed: data-only response",
  "profile": "legacy-canonical",
  "rules": ["C-06", "C-07", "C-11"],
  "upstream": { "repo": "Tencent/VasSonic", "sha": "59936beff656d4b5718ff6444d6c5e001a2c5231" },
  "sources": ["upstream:sonic-java/src/main/java/com/github/tencent/SonicFilter.java:105-144"],
  "evidence": "trace",
  "traces": {
    "legacy-java": "evidence/traces/server/java/S06-data-change.http",
    "legacy-node": "evidence/traces/server/node/S06-data-change.http",
    "legacy-php": "evidence/traces/server/php/S06-data-change.http"
  },
  "page": "b",
  "app": { "status": 200, "headers": [["content-type", "text/html; charset=utf-8"]] },
  "request": {
    "method": "GET",
    "headers": [
      ["accept-encoding", "gzip"],
      ["accept-diff", "true"],
      ["if-none-match", "{{etag:a}}"],
      ["template-tag", "{{tag:a}}"]
    ]
  }
}
```

| Field | Rule |
|---|---|
| `id` | The directory name |
| `profile` | `legacy-canonical` |
| `rules` | Rules of legacy wire §10 (`C-01`…`C-16`) that the case checks |
| `upstream` | Always the pinned repository and SHA above |
| `sources` | At least one `upstream:<path>:<line>` or `docs:<page>#<anchor>` reference |
| `evidence` | `trace` (the scenario was captured from the upstream servers) or `code-reading` |
| `traces` | Only with `evidence: trace`: the stored trace of the same request for each upstream profile |
| `page` | The application body: `pages/<page>.html` |
| `app` | The application response before the legacy step: status and field lines (lower-case names, order kept); default `{ "status": 200, "headers": [["content-type", "text/html; charset=utf-8"]] }` |
| `request.method` | Default `GET` |
| `request.target` | Default `https://shop.example.com/catalog` |
| `request.headers` | Field lines in order; a name can repeat (one line each). Placeholders below |
| `level` | Optional, `must` (default) or `should` |

**Placeholders** (the only computed values; every other byte is literal):

| Placeholder | Value |
|---|---|
| `{{etag:<page>}}` | Lowercase hex SHA-1 of `pages/<page>.html` (C-04) |
| `{{ETAG:<page>}}` | The same in uppercase hex |
| `{{tag:<page>}}` | `template-tag` of the page under the profile of the fixture (C-08 for `legacy-canonical`); the empty string when the profile sends no `template-tag` for that page |
| `{{TAG:<page>}}` | The same in uppercase hex |

A placeholder can be part of a value, for example `"\"{{etag:a}}\""` or `"W/\"{{etag:a}}\""`.

## Profile `case.json`

```json
{
  "id": "FX-LEG-DATA-CHANGE--JAVA",
  "description": "legacy-java: HashMap order and Gson escaping of the data body; Cache-Control no-cache",
  "profile": "legacy-java",
  "replaces": "FX-LEG-DATA-CHANGE",
  "divergences": ["D-08", "D-09"],
  "sources": ["upstream:sonic-java/src/main/java/com/github/tencent/SonicFilter.java:60-149"],
  "trace": "evidence/traces/server/java/S06-data-change.http"
}
```

A profile fixture takes `page`, `app` and `request` of the replaced fixture; the placeholders are resolved under its own profile. Optional `not_reproduced`: the profile does not reproduce this unsafe upstream behavior (DL-069, DL-082). It takes only `"U-11"` or `"U-13"`, and each has its own check: the generator checks that the trace shows the documented difference, not that it equals the expected response (see `tools/legacy-fixtures/README.md`). The profile fixtures of S24 to S27 (`REDIRECT`, `PASS-NOT-FOUND`, `PASS-POST`, `PASS-HEAD`) have `not_reproduced: "U-13"` and expect the C-01 pass-through.

## `expected.json`

Generated.

```json
{
  "id": "FX-LEG-DATA-CHANGE",
  "profile": "legacy-canonical",
  "level": "must",
  "request": { "method": "GET", "target": "https://shop.example.com/catalog", "headers": [["accept-encoding", "gzip"], ["accept-diff", "true"], ["if-none-match", "3e31…"], ["template-tag", "3c77…"]] },
  "status": 200,
  "fields": {
    "etag": ["4c33…"],
    "template-tag": ["3c77…"],
    "template-change": ["false"],
    "cache-offline": ["true"],
    "cache-control": ["no-cache, private"],
    "content-type": ["text/html; charset=utf-8"],
    "sonic-etag-key": [],
    "cdn-cache-control": [],
    "surrogate-control": [],
    "vary": ["template-tag"]
  },
  "body": { "kind": "data", "data": { "{title}": "<title>Shop</title>", "{price}": "…" }, "template_tag": "3c77…", "html_sha1": "4c33…", "diff": "" },
  "split": { "applied": true, "template_sha1": "3c77…", "keys": ["{title}", "{price}", "{stock}"], "rebuild_sha1": "4c33…" },
  "profiles_same": ["legacy-php"]
}
```

| Member | Rule |
|---|---|
| `fields` | For each listed name, the exact list of field values in order (one per field line; names compare case-insensitively). `[]` means the field must be absent. Names not listed are not compared, except `Content-Length` (equal to the body length when present) and `Content-Encoding` (absent or `gzip`, DL-073; the runner decodes `gzip` first) |
| `body.kind` | `page` (exactly the bytes of the application body), `data` (a JSON object with exactly the members `data`, `template-tag`, `html-sha1`, `diff`; compared as JSON values, D-08), `none` (no body) |
| `split` | The template and data split of the page under the profile: `applied` (false when the profile does not split), `template_sha1`, `keys` in order, `rebuild_sha1` (SHA-1 of the template with each placeholder replaced once by its value, in template order; equals the etag when the split is consistent). For core and SDK unit tests; the runner does not use it |
| `profiles_same` | Canonical fixtures only: the upstream profiles whose stored trace gives this exact expected response (no profile fixture needed) |
| `trace` | Profile fixtures only: copied from `case.json` |

The runner with `--profile legacy-canonical` runs every canonical fixture. With `--profile legacy-java` (or node, php) it runs the canonical fixtures that list that profile in `profiles_same` and the profile fixtures of that profile: only behavior confirmed by an upstream trace (DL-068).

## Generator checks (`gen.mjs --check`)

1. Every `expected.json` equals the regenerated one byte for byte; no unknown or missing files.
2. Every trace-backed profile response (status, the fields `etag`, `template-tag`, `template-change`, `cache-offline`, `cache-control`, `content-type`, `sonic-etag-key`, and the decoded body: exact for `page`, as JSON values for `data`) equals the stored trace, except a fixture with `not_reproduced`, which gets the check of its item. `content-type` is compared on every response (also a `304`) as a media type, not byte for byte. The request equals the trace request: by method and field lines, and for a trace with a `Host` first line (S22 to S29) also by authority and path. `vary`, `cdn-cache-control` and `surrogate-control` are not compared with the traces: every profile follows C-13 and C-15 (U-12, H-111).
3. `OVERRIDE_NOT_NEEDED`: a profile fixture whose expected response equals the canonical one. A fixture with `not_reproduced` is skipped: a U-13 fixture expects the canonical pass-through, and check 2 proves that its trace differs.
4. `OVERRIDE_MISSING`: a trace-backed canonical fixture whose trace for a profile differs from the canonical expected response, with no profile fixture.
5. Every `rules` item exists in legacy wire §10; every C-rule is covered by at least one fixture.

## Rules

1. Files are exact bytes (`.gitattributes`: `fixtures/** -text`).
2. A fixture changes only with review by the protocol owner. Never change a fixture to make an implementation pass.
3. One behavior per fixture.
4. No real user data, tokens or domains. Use `example.com`.
