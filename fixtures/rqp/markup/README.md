# RQP markup fixtures

<!-- SPDX-FileCopyrightText: The Rivqen Authors -->

Golden fixtures for the RQP markup rules (`docs/engineering/protocol/markup.md`). Every RQP parser runs them. Format fixed by the architect for WP-17 S1.

## Layout

```text
fixtures/rqp/markup/FX-RQ-MARKUP-<NAME>/
├── input.html      # the document, exact bytes
├── fixture.json    # written by a person: id, description, rules, expected blocks
└── expected.json   # generated by tools/rqp-markup/gen.py; never edited by hand
```

## `fixture.json`

```json
{
  "id": "FX-RQ-MARKUP-SIMPLE",
  "description": "One html block in the body",
  "rules": ["M-01", "M-02"],
  "expect": {
    "valid": true,
    "blocks": [
      { "id": "price", "format": "html", "start_tag": "<p data-rq-block=\"price\">", "content": "120.00" }
    ]
  }
}
```

Invalid document: `"expect": { "valid": false, "error": "RQP_MARKUP_DUPLICATE" }`.

| Field | Rule |
|---|---|
| `start_tag` | The exact start-tag text as it is in `input.html`. It must occur exactly once in the input. |
| `content` | The exact block content (the text between the start tag and the end tag). Optional `content_file` instead: a file name in the fixture directory (for large or binary-sensitive content). |
| `rules` | The rule IDs of `markup.md` that the fixture covers |

The generator finds `start_tag`, checks that `content` follows it, computes the byte offsets, the hashes and the revisions (algorithm: `tools/rqp-markup/CONTRACT.md` §4), and writes `expected.json`. The generator does not parse HTML. It is an independent oracle: the expected blocks come from a person, not from a parser.

## Rules

1. Files are exact bytes. Do not let an editor change line ends or add a final line feed.
2. A fixture changes only with review by the protocol owner. Never change a fixture to make a parser pass.
3. One error per invalid fixture.
4. No real user data, tokens or domains. Use `example.com`.
