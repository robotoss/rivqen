Golden fixtures for RQP negotiation, manifest and patch (`docs/engineering/protocol/negotiation.md`, `manifest-patch.md`). A server SDK and the server demo must give the expected response for every case before SDK code is written (WP-17 acceptance). Format fixed by the architect for WP-17 S2. Catalog: `docs/engineering/protocol/fixtures.md` §4.1.

## Layout

```text
fixtures/rqp/protocol/
├── pages/<page-id>.html          # application page bytes, exact (generated pages by a recipe in gen.py)
└── FX-RQ-<NAME>/
    ├── case.json                 # written by a person: the request and the application response
    └── expected.json             # generated by tools/rqp-protocol/gen.mjs; never edited by hand
```

## `case.json`

```json
{
  "id": "FX-RQ-P09-DELTA",
  "description": "Delta with only the changed block",
  "rules": ["RQP-08", "RQP-11"],
  "page": "page-b",
  "client_page": "page-a",
  "app": { "status": 200, "headers": [["content-type", "text/html; charset=utf-8"], ["cache-control", "no-cache"]] },
  "request": {
    "method": "GET",
    "headers": [
      ["rq-version", "1"],
      ["rq-capabilities", "(block-patch)"],
      ["accept", "text/html, application/vnd.rivqen.delta+json"],
      ["if-none-match", "{{r1:page-a}}"],
      ["rq-have", "t={{t1:page-a}}, b={{have:page-a}}"]
    ]
  }
}
```

| Field | Rule |
|---|---|
| `page` | The page the application renders now (`pages/<id>.html`) |
| `client_page` | Optional. The page the client holds; used only by placeholders |
| `app` | The application response before the RQP server step: status and header lines (lower-case names, order kept) |
| `request.headers` | Header lines in order; a name can repeat (one line each). Placeholders: `{{r1:<page>}}` → `"r1.…"` (with quotes), `{{t1:<page>}}` → `t1.…` (Token), `{{have:<page>}}` → `:<base64>:` of the 64-bit prefixes (H-44). The generator replaces them; the harness gets the final bytes in `expected.json` |

Placeholders are the only computed values in `case.json`. Every other byte is literal.

## `expected.json`

Generated. Fields: `request` (final header lines), `status`, `headers_required` (name → exact value), `headers_forbidden` (names), `body` (`"full"` — the page with the manifest inserted, compared by its `r1.` and manifest; `"delta"` — envelope fields `base_revision`, `next_revision`, `template_revision` and the ordered list of changed block ids; `"app"` — the application body unchanged; `"none"`).

## Rules

1. Files are exact bytes (`.gitattributes`: `fixtures/** -text`).
2. A fixture changes only with review by the protocol owner. Never change a fixture to make an implementation pass.
3. One behavior per fixture.
4. No real user data, tokens or domains. Use `example.com`.
5. Block analysis of pages uses the RQP markup rules; the generator may call the Node.js markup candidate (`tools/rqp-markup/node/src/cli.mjs`).
